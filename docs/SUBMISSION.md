## Description

**The problem.** When your funds sit on several chains, nobody watches the whole picture. Keeping a simple 60/40 mix means checking every chain, adding it up and trading by hand, or running a bot on a server you have to keep alive and trust. The same goes for a liquidity position: you only find out it left its range when you happen to look.

**What Omni Autopilot does.** You set your rules once: target mix, comfort zone, LP price range, journal schedule. A single reactive contract on Reactive Lasna then:

1. **Tracks.** It subscribes to every tETH/tUSD `Transfer` in or out of the wallet on Ethereum Sepolia, Base Sepolia and Unichain Sepolia, and keeps a per-chain ledger on-chain.
2. **Prices.** It reads the price from a Uniswap-V2-style pool's `Sync` events.
3. **Rebalances.** When the cross-chain ETH share leaves 60% ± 5%, it calls the vault on Base Sepolia to trade back to target. A transfer on Unichain or Sepolia causes a trade on Base.
4. **Alerts.** When the Unichain pool price leaves your LP range, or comes back, it writes an alert to a Journal on Base.
5. **Journals and self-heals.** Reactive's cron wakes it to write portfolio snapshots, then asks a beacon on each chain to re-publish real balances, so a missed event can't leave the books wrong.

The vault, journal and beacons subscribe back too: when a callback lands, the autopilot sees the result event, so every loop closes on-chain.

**Why Reactive is doing real work.** All subscriptions, the ledger, the decision logic and the schedule live in the reactive contract; nothing off-chain decides anything. On Omni there is no separate ReactVM, so the dashboard reads the live ledger with a plain `eth_call`. With ~1 s blocks and instant finality, the measured latency from origin event to destination callback is **1–2 seconds**.

**Safety.** The vault only accepts calls from the callback proxy carrying this autopilot's address (`onlyServiceProvider` + `onlyCallbackSender`). It enforces a timestamp-based cooldown (Base makes 200 ms blocks), a per-trade cap and a minimum-output check. It never reverts on a rule check; it emits `RebalanceSkipped`, so the autopilot always hears back. `react()` never reverts on unexpected input, de-duplicates logs matched by two subscriptions, and spreads heavy cron work across ticks to stay under the 900k gas cap.

**Craft.** 31 Foundry tests, including a fuzz test that the on-chain books always match real balances, run through a harness that simulates Reactive's subscription matching and callback delivery. The README has diagrams and step-by-step deploy and demo commands. There is a polished live dashboard with plain-English status, per-chain cards, a full-loop timeline with latency, an activity feed and a history chart.

**Honest notes.** Testnets only; tETH/tUSD are test tokens; the watched wallet is a demo wallet; all activity was generated by us for the demo.
